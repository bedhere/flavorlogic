# 项目结构说明

打开 xm-flavor_logic，先从 frontend 找页面，再从 backend 的同名业务模块找后端。根目录 pom.xml 是统一构建入口。

```text
xm-flavor_logic/
├── frontend/                       正式前端
│   ├── index.html / index.js        首页
│   ├── modules/                    auth、dashboard、recipe、analysis、article、knowledge、profile、public
│   ├── admin/                      user、ingredient、article、analysis、knowledge
│   └── shared/                     core、components、styles、assets、vendor
├── backend/
│   ├── pom.xml                     Java 11 / Servlet 4 / JDBC / WAR
│   └── src/main/
│       ├── java/com/flavorlogic/
│       │   ├── module/             user、recipe、analysis、ingredient、region、article、knowledge、dashboard
│       │   │   └── 业务模块/        servlet、service、dao、model；计算业务有 engine
│       │   └── common/             过滤器、HTTP/事务模板、持久化、公共模型和工具
│       ├── resources/              数据库配置
│       └── webapp/WEB-INF/web.xml   容器配置
├── database/                       schema、migrations、seeds、demo
├── docs/                           结构、功能对照、接口、数据库、答辩
├── scripts/
│   ├── start.ps1 / stop.ps1         启动、停止
│   ├── data/                       初始化与导入
│   └── dev/                        结构、语法、SQL、运行检查
├── .runtime/                       本机运行、验证和备份；Git 忽略
├── pom.xml                         统一构建入口
└── README.md                       项目入口
```

## 固定查找顺序

提交分析的定位路径：

1. [analysis-run.html](../frontend/modules/analysis/analysis-run.html)：界面与资源加载。
2. 同目录 analysis-run.js 的 submitAnalysis：收集输入；analysis-api.js：实际接口地址。
3. backend/src/main/java/com/flavorlogic/module/analysis/servlet/AnalysisServlet.java：HTTP 请求入口。
4. 同模块 service/impl/AnalysisServiceImpl.java：归属校验、事务与计算编排。
5. 同模块 engine：算法；dao/impl：参数化 SQL。
6. database/schema/flavor_logic.sql：表、字段、索引、外键。

其他业务从 [功能源码对照](02-功能源码对照.md) 查。该文档先列具体操作的前端方法、HTTP、业务方法、DAO 方法和主要读写表，再列全页面请求和由表反查 DAO 的索引。

## 职责与命名

| 类型 | 职责 |
|---|---|
| 页面.html / 同目录页面.js | 界面 / 事件、输入、渲染、跳转 |
| 同目录业务-api.js | 本模块真实接口地址；传入动态编号、查询串与请求体 |
| shared/core/api.js | HTTP、JSON、业务错误、登录失效 |
| Servlet | 路由、参数绑定、登录用户、统一响应 |
| Service / impl | 业务契约、校验、事务编排 |
| DAO / impl | SQL、参数绑定、结果映射 |
| model | 实体、请求、结果、快照 |
| engine | 算法；不访问 HTTP 或数据库 |

HTML 和交互 JS 同名同目录；Java 保留职责后缀。JSON/Java 属性用 camelCase，SQL 表/列用 snake_case。

业务词汇固定为 recipe、analysis、ingredient、region、article、knowledge、user、dashboard。前端登录页归 auth，后端认证归 user。文章与来源审核分别归 article、knowledge。原 MetaService 已拆成 IngredientService、RegionService、RuleService；规则业务归 analysis。

每个 HTML 的 app-root 指向前端根目录，公共层据此计算部署上下文。加载顺序：第三方库 → common → api → 本模块 API 文件 → 组件 → 页面。旧 HTML 地址通过 LegacyRouteFilter 跳转并保留参数；旧 assets 封面路径通过公共工具和兼容过滤器处理。

## 构建与维护

```powershell
mvn -B clean package
# 产物：backend/target/flavorlogic.war
& ./scripts/start.ps1 -Build -TomcatHome "你的 Tomcat 9 目录"
& ./scripts/stop.ps1 -TomcatHome "你的 Tomcat 9 目录"
python scripts/dev/source-index.py
python scripts/dev/source-index.py --check
python scripts/dev/check-sql-layout.py
node scripts/dev/check-frontend.js
node scripts/dev/check-features-page.js
```

修改 frontend 或 backend/src。backend/target 和 .runtime/tomcat/webapps 是生成副本。IDE 重新导入根 pom.xml 识别 backend 模块。

新增操作后更新 docs/03-接口说明.md 与 docs/reference/业务流程映射.json，再生成索引。结构检查核对页面配对、资源/导航、加载顺序、API、Servlet，以及操作记录的类/方法/表存在性。类级依赖集合不能证明一次请求访问全部表。

迁移记录在 docs/reference/文件迁移清单.json、Java类位置映射.json、页面地址映射.json。迁移前本机备份在 .runtime/backups/before-structure-20261014.zip。
