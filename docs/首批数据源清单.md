# 首批数据源清单

## 当前状态

本清单只登记候选来源，不代表项目已经取得自动采集许可。对应 SQL 会把 `crawl_allowed` 设为 `0`，因此执行后不会触发网络访问。

正式启用某个来源前，需要人工确认：

1. 当前服务条款和数据许可是否允许项目用途；
2. robots.txt 和 API 使用限制；
3. 请求频率、身份标识和 API Key 要求；
4. 要保存的字段、单位和适用条件；
5. 是否允许保存正文、摘要或只保存引用信息。

## 第一批候选来源

| 来源 | 类型 | 第一阶段用途 | 暂不做的事情 |
|---|---|---|---|
| USDA FoodData Central | API | 营养成分候选字段，如能量、蛋白质、脂肪、钠 | 不直接生成风味维度评分 |
| Open Food Facts | DATASET/API | 包装食品标签和营养字段候选 | 不把众包字段当作唯一科学证据 |
| PubMed / NCBI | PAPER/API | 文献元数据、摘要和研究结论线索 | 不批量保存没有明确许可的全文 |

## 首批验收规模

- 10～20 个来源文档；
- 5～10 种核心食材；
- 20～50 条证据声明；
- 所有采集结果先进入 `REVIEW_PENDING`；
- 至少完成 1 条“来源文档 → 证据声明 → 食材属性版本 → 应用到主表”的完整链路。

## 数据进入规则

营养数据库适合提供结构化数值；文献适合提供研究证据；网页文章和产品介绍只能作为待审核线索。任何来源都不能直接覆盖 `ingredient` 主表，也不能直接改变 Java 规则。

## 对应脚本

执行数据库初始化后，可以单独执行：

```sql
SOURCE database/source_sites_seed.sql;
```

执行完成后，后台来源站点页面会显示三个停用自动采集的候选来源。确认条款和字段映射后，再逐个修改为允许采集。
