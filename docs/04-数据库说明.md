# 数据库说明

业务库名仍为 flavor_logic，表名、字段和 JSON 协议保持原样。建表正本为 [schema/flavor_logic.sql](../database/schema/flavor_logic.sql)，执行顺序见 [数据库脚本说明](../database/README.md)。

| 业务 | 表与用途 |
|---|---|
| user | sys_user：身份、角色、密码哈希、登录时间 |
| recipe | recipe、recipe_item：主表与配料明细；goal_target、flavor_knowledge：目标和候选知识 |
| analysis | analysis_task：输入快照与状态；analysis_result：计算输出；analysis_feedback：反馈；flavor_rule：规则 |
| ingredient / region | ingredient：八维基础属性；region_profile：区域权重 |
| article | article_category、knowledge_article：分类、正文、状态、浏览量 |
| knowledge | source_site、crawl_job、source_document：来源、采集、审核文档；evidence_claim、ingredient_attribute_version、rule_evidence：声明、属性版本、证据关联 |
| 预留定义 | ingredient_pairing、ai_call_log：有建表或种子，当前未检测到业务 DAO 访问 |

article 与 knowledge 是两类业务。来源资料导入不会自动修改食材属性；须经过属性版本创建、审核、应用。不能把预留表描述为已进入实际合成或 AI 调用链路。

## 字段对应

| JSON / Java | SQL 存储 | 转换位置 |
|---|---|---|
| Recipe.name | recipe.name | RecipeDaoImpl 参数绑定 / mapRow |
| RecipeItem.ingredientId / amount | recipe_item.ingredient_id / amount | RecipeItemDaoImpl |
| AnalysisRequest.recipeId → AnalysisTask.recipeId | analysis_task.recipe_id | Servlet → Service → DAO |
| AnalysisRequest.targetItems | target_snapshot_json 中的目标配料与属性 | AnalysisServiceImpl.buildTargetSnapshot |
| constraints | analysis_task.constraint_json | Service 序列化；详情读取时解析 |
| baselineSnapshot / targetSnapshot | baseline_snapshot_json / target_snapshot_json | AnalysisTaskDaoImpl |
| result.baseline / target | analysis_result.baseline_json / target_json | AnalysisResultDaoImpl |
| result.deltas / suggestions | delta_json / suggestion_json | Service 序列化与解析 |
| AnalysisFeedback.rating / trialResult | analysis_feedback.rating / trial_result | AnalysisFeedbackDaoImpl.upsert |

请求对象不必对应一张表，例如 AnalysisRequest 是业务输入，不存在同名表。Java/JSON 的 camelCase 与 SQL 的 snake_case 在 DAO 中映射。

## 关联与事务

recipe_item.recipe_id 关联配方；analysis_task.recipe_id 关联基准配方；analysis_result.task_id 唯一关联任务；反馈 task_id + user_id 唯一，再次提交更新同一行。

配方主表与明细共用写事务。分析 PENDING、RUNNING 分阶段提交，结果与 COMPLETED 同事务；异常后另开事务标记 FAILED。反馈单独写事务。任务快照保存当时食材属性与用量，结果保存计算输出；回看读保存内容，不重新执行引擎。

MySQL 5.7 不强制执行 CHECK，业务校验在 Service。DAO 通过 JdbcHelper / PreparedStatement 参数化，BaseService 管理连接与提交回滚。具体方法见 [功能源码对照](02-功能源码对照.md)，完整过程见 [答辩流程](05-答辩流程.md)。
