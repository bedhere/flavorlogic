# 食之有理 FlavorLogic 接口说明

> 基础地址：`http://localhost:8080/flavorlogic`（下文路径均省略该前缀）
> 数据格式：请求与响应均为 `application/json; charset=UTF-8`
> 会话：登录成功后由 `JSESSIONID` Cookie 维持，有效期 30 分钟

---

## 一、统一约定

### 1.1 响应结构

```json
{
  "code": 0,
  "message": "success",
  "data": { },
  "timestamp": 1789520293058
}
```

| 字段 | 说明 |
|---|---|
| `code` | `0` 表示成功；非 0 为业务码（见 1.3） |
| `message` | 面向用户的提示信息，失败时可直接展示 |
| `data` | 业务数据，可能是对象、数组或 `null` |
| `timestamp` | 服务端时间戳（毫秒） |

### 1.2 HTTP 状态码约定

| 状态码 | 含义 | 前端处理 |
|---|---|---|
| 200 | 成功，或业务失败（`code != 0`） | 判断 `code`，失败就地提示 |
| 401 | 未登录 / 会话失效 | 统一跳转 `login.html?redirect=原路径` |
| 403 | 已登录但无权限（越权访问他人数据、非管理员访问后台） | 提示无权限 |
| 404 | 资源不存在 | 提示不存在 |
| 405 | 请求方法不被该接口支持 | — |

### 1.3 业务码

| 业务码 | 场景 |
|---|---|
| 0 | 成功 |
| 400 | 参数校验失败（提示信息可直接展示） |
| 401 / 403 / 404 | 同 HTTP 状态码 |
| 409 | 数据冲突：用户名已注册、食材名称重复、文章来源地址或正文指纹重复 |
| 500 | 服务器内部错误（详细堆栈只记录在服务端日志） |

### 1.4 权限说明

| 标记 | 含义 |
|---|---|
| 公开 | 无需登录（`AuthFilter` 放行） |
| 登录 | 需要登录（未登录返回 401，页面跳登录页） |
| 管理员 | 需要 `role = ADMIN`（`AdminFilter` 拦截，否则 403） |

## 二、认证接口

### POST /api/auth/register —— 注册（公开）

请求体：

```json
{ "username": "demo", "nickname": "研发小食", "password": "Demo@123", "confirmPassword": "Demo@123" }
```

校验规则：用户名 2-20 位，支持中文、字母、数字与下划线且唯一；昵称必填 ≤50；密码 6-20 位且两次一致。
**注册只创建账号，不建立会话**（返回 `message = 注册成功，请使用新账号登录`），
前端随后跳转到登录页并自动填好用户名，由用户手动输入密码登录。

### POST /api/auth/login —— 登录（公开）

```json
{ "username": "demo", "password": "Demo@123" }
```

成功返回：

```json
{ "code": 0, "data": { "id": 2, "username": "demo", "nickname": "研发小食", "role": "USER", "isAdmin": false } }
```

登录成功会**重建 Session**（防会话固定攻击）并记录 `last_login_at`；账号被禁用返回 403。

### POST /api/auth/logout —— 退出（公开）

销毁 Session，返回 `{"code":0}`。

### GET /api/auth/me —— 当前用户（公开）

未登录返回 401；前端用它判断登录态与是否显示后台入口。

### POST /api/auth/password —— 修改密码（登录）

```json
{ "oldPassword": "Demo@123", "newPassword": "Demo@456", "confirmPassword": "Demo@456" }
```

原密码错误、新旧相同、两次不一致均返回 400。

## 三、研发知识库

### GET /api/articles —— 文章列表（公开）

| 参数 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `categoryId` | long | 否 | 分类筛选 |
| `keyword` | string | 否 | 标题 / 摘要模糊匹配 |
| `page` | int | 否 | 默认 1 |
| `pageSize` | int | 否 | 默认 10，最大 50 |

仅返回**已发布**文章，列表不含正文（减少传输量），带出分类名与作者昵称。

```json
{ "code": 0, "data": { "list": [ { "id": 1, "title": "八维风味向量…", "categoryName": "风味科学", "authorName": "系统管理员", "summary": "…", "viewCount": 3, "publishedAt": "2026-09-16 09:12:00" } ],
  "total": 6, "page": 1, "pageSize": 10, "totalPages": 1 } }
```

### GET /api/articles/{id} —— 文章详情（公开）

浏览数 +1；正文经白名单过滤（移除 script/style/iframe 与内联事件）；同时返回同分类相关文章。

```json
{ "code": 0, "data": { "article": { "id": 1, "title": "…", "content": "<h2>…</h2>", "sourceName": "…", "sourceUrl": "…" },
  "related": [ { "id": 5, "title": "…" } ] } }
```

草稿或下架文章对普通访问返回 403/404。

### GET /api/categories —— 文章分类（公开）

返回启用中的分类数组，按 `sort_no` 升序。

## 四、配方管理

### GET /api/recipes —— 我的配方（登录）

| 参数 | 说明 |
|---|---|
| `keyword` | 配方名称模糊匹配 |
| `page` / `pageSize` | 默认 1 / 10 |

列表项含 `itemCount`（配料条数）；仅返回当前用户、未删除的配方。

### GET /api/recipes/profiles —— 全部配方的风味画像（登录）

**只算不存**：不创建分析任务、不写分析历史（否则分析历史会被大量无信息量的记录挤占）。

返回的 `data` 是**数组**（不是对象），每项：

| 字段 | 说明 |
|---|---|
| `recipeId` / `recipeName` / `versionNo` | 配方标识 |
| `scores` | 八维得分（`sweet` … `fat_aroma`），口径与正式分析完全一致 |
| `completeness` | 数据完整度 0-100：有属性数据的用量占配方总用量的百分比 |
| `itemCount` / `totalAmount` | 有效配料条数、配方总用量 |
| `hasMissingAttribute` | 是否含缺少风味属性数据的配料 |

单个配方算不出画像时会被跳过而不是报错；一次最多返回 200 条。

### GET /api/recipes/{id}/compose —— **配方合成**（登录）

**依据研发目标直接生成一份可执行的新配方**，是本系统的核心接口。**只算不存**。

| 参数 | 说明 |
|---|---|
| `goalType` | 研发目标：`REPLACE` / `REDUCE_SUGAR` / `REDUCE_FAT` / `ADJUST_STIMULATION` / `REGION_ADAPT` / `GENERAL` |
| `regionProfileId` | 目标区域编号，可选 |
| `allergens` | 过敏原/禁用清单，逗号分隔，可选 |

用 GET 而非 POST：它不创建任何记录（幂等），参数少且便于在浏览器里直接验证。

返回 `data` 结构：

| 字段 | 说明 |
|---|---|
| `items` | **生成的新配方配料表**：食材、用量、单位、占比，以及 `baseAmount` / `added` / `changed` 标记 |
| `adjustments` | 改动清单：每项含知识卡编码、参考区间与**取值理由** |
| `checks` | 逐维达标情况：目标值、预测值、偏差、是否在容差内（容差 5） |
| `warnings` | 需要人工知晓的提示（复配体系未自动处理、候选不在食材库中等） |
| `baselineVector` / `predictedVector` | 基准与合成后的风味向量 |

合成分两轮且顺序不可颠倒：**先成分层**（按目标模板倍率缩放指定类目用量），
**再风味层**（逐维算缺口、用知识卡候选补缺口）。每调整一维就重算一次向量，
因为加料会改变配方总量即分母，不重算会让后续维度读到过时的缺口。

候选筛选有四道关卡，任何一道不过都会把原因写进 `warnings` 而不静默跳过：

| 关卡 | 规则 | 不过时的处理 |
|---|---|---|
| 方向匹配 | 缺口为正 → 接受 `ADD` / `REPLACE`；缺口为负 → 只接受 `REDUCE`；`NOTICE` 不参与 | 提示"没有方向匹配的可用知识卡" |
| **可行性** | 需要提高维度时，候选的该维度属性值必须**高于目标值** | 提示"候选达不到目标"，**并说明原因**（见下） |
| 单一候选 | 候选含「+」的复配体系跳过 | 提示"复配体系无法自动确定配比" |
| 有用量区间 | `amount_min` / `amount_max` 必须都有值 | 提示"没有用量区间，无法换算" |

**关于可行性关卡**：维度得分是各配料属性按用量占比的加权平均，**结果不会超过参与计算的最高属性值**。
所以属性值低于目标的候选，加多少都到不了目标，只会白白稀释其他维度。
例如目标甜度 77.4 而赤藓糖醇的甜度属性只有 65，加它只会把甜度往 65 拉，越加越远。

### 已知的模型局限（会在 `warnings` 中显式说明）

某一维度**已按知识卡调整但预测仍未达标**时，`warnings` 会明确说明「这属于模型表达力问题而非配方问题」：
当前引擎按**用量占比**加权，无法体现高倍原料的实际效力——例如 0.02% 的甜菊糖苷在真实配方中
可替代相当量的蔗糖，但模型只按它 0.02% 的占比计算，因此改善微乎其微。

**配方中的用量依据知识卡参考区间确定，是可信的；预测偏差属于待升级项**（见《计设计划》的模型演进部分）。
把这个矛盾讲清楚，用户才知道该信配方还是信预测。

### GET /api/recipes/{id} —— 配方详情（登录）

返回配方主体 + `items` 明细（含食材分类与 `attributeAvailable` 标记）。
非本人配方返回 403，已删除返回 404。

### POST /api/recipes —— 新建配方（登录）

```json
{
  "name": "香辣牛肉干", "productType": "休闲肉制品",
  "processNote": "腌制 12 小时后 70℃ 热风干燥", "remark": "第一版",
  "items": [
    { "ingredientId": 12, "ingredientName": "牛肉", "amount": 100, "unit": "g" },
    { "ingredientId": 2,  "ingredientName": "食盐", "amount": 1.5, "unit": "g" }
  ]
}
```

校验：名称必填 ≤100；至少 1 项、最多 50 项配料；用量 > 0；同配方内食材不可重复。
配方与明细在**同一事务**中写入，任一步失败整体回滚。

### PUT /api/recipes/{id} —— 修改配方（登录）

请求体同上（`id` 以路径为准）。明细整体替换，`version_no` 自动 +1。

### DELETE /api/recipes/{id} —— 删除配方（登录）

软删除（`status = 0`），历史分析记录仍可回看当时的配方快照。

## 五、风味分析（项目主功能）

### POST /api/analysis —— 创建并执行分析（登录）

```json
{
  "taskName": "控脂 25%：减油与主料替换后的脂香补偿",
  "recipeId": 7,
  "goalType": "REDUCE_FAT",
  "regionProfileId": 2,
  "constraints": { "costLimit": 3.5, "healthGoal": "LOW_FAT", "allergens": ["花生"], "note": "维持整体风味" },
  "targetItems": [
    { "ingredientId": 13, "ingredientName": "猪肉", "amount": 70, "unit": "g" },
    { "ingredientId": 11, "ingredientName": "鸡胸肉", "amount": 30, "unit": "g" }
  ]
}
```

| 字段 | 必填 | 说明 |
|---|---|---|
| `taskName` | 否 | 为空时按「配方名 · 目标类型」生成 |
| `recipeId` | 是 | 基准配方编号（校验归属） |
| `goalType` | 否 | `GENERAL`（默认）/ `REPLACE` / `REDUCE_SUGAR` / `REDUCE_FAT` / `ADJUST_STIMULATION` / `REGION_ADAPT` |
| `regionProfileId` | 否 | 目标区域画像编号，选择后基准与目标同时按区域权重折算 |
| `constraints` | 否 | 成本上限、健康化目标、过敏原（命中的候选食材会从建议中剔除） |
| `targetItems` | 是 | 目标方案配料；`ingredientId` 为空时按食材名自动匹配 |

执行流程：任务先以 `PENDING` 落库并提交 → 流转 `RUNNING` → 计算并写入结果 → 流转 `COMPLETED`；
计算失败则流转 `FAILED` 并记录失败原因（失败任务同样可以在历史记录中看到）。

响应即完整的分析详情（结构见下）。

### GET /api/analysis/history —— 分析历史（登录）

| 参数 | 说明 |
|---|---|
| `keyword` | 任务名或配方名模糊匹配 |
| `goalType` / `status` | 类型 / 状态筛选（`PENDING`、`RUNNING`、`COMPLETED`、`FAILED`） |
| `page` / `pageSize` | 默认 1 / 10 |

### GET /api/analysis/{id} —— 分析详情（登录）

```json
{
  "code": 0,
  "data": {
    "id": 8, "taskName": "…", "goalType": "REDUCE_FAT", "targetRegion": "西南地区",
    "status": "COMPLETED", "createdAt": "…", "finishedAt": "…", "recipeName": "低脂红烧肉（控脂基线）",
    "constraints": { "costLimit": 3.5, "healthGoal": "LOW_FAT", "allergens": ["花生"] },
    "baselineSnapshot": { "recipeName": "…", "totalAmount": 115.5,
      "items": [ { "ingredientName": "猪肉", "amount": 100, "unit": "g",
                   "attributes": { "sweet": 0, "fat_aroma": 82 }, "attributeAvailable": true } ] },
    "targetSnapshot": { "…": "同上结构" },

      "confidence": 85.33, "dataCompleteness": 100.00,

      "explanation": "一、计算口径…四、免责声明…",
      "engineVersion": "RULE-1.0",
      "baseline": { "scores": { "sweet": 0.94, "fat_aroma": 77.30 } },
      "target":   { "scores": { "sweet": 0.99, "fat_aroma": 61.51 } },
      "deltas": [ { "dimension": "fat_aroma", "dimensionLabel": "脂香",
                    "baseline": 77.30, "target": 61.51, "diff": -15.79, "changePercent": -20.43,

                         "actionText": "提示关注", "dimensionLabel": "脂香", "target": "「油脂」类原料",
                         "referenceRange": "无固定幅度，按打样结果微调",
```

八维维度编码固定：`sweet` 甜、`salty` 咸、`sour` 酸、`bitter` 苦、`umami` 鲜、`spicy` 辣、`numbing` 麻、`fat_aroma` 脂香。

### DELETE /api/analysis/{id} —— 删除历史任务（登录）

结果与反馈随外键级联删除；仅能删除本人的任务。

### POST /api/analysis/{id}/feedback —— 提交试产反馈（登录）

```json
{ "helpful": 1, "rating": 5, "comment": "第 2 版一次通过", "trialResult": "PASSED" }
```

`helpful` ∈ {0,1}；`rating` ∈ 1-5；`trialResult` ∈ `NOT_TRIED` / `PASSED` / `PARTIAL` / `FAILED`。
同一用户对同一任务**只有一条反馈**（重复提交为更新，依赖唯一键 `uk_feedback_task_user`）。

## 七、配料调配知识库与 AI 增强（接口预留，当前版本尚未实现）

> 本节接口依赖 `flavor_knowledge`、`ingredient_pairing`、`ai_call_log` 三张表。
> 表结构与基础数据已在 `database/flavor_logic.sql` 中建好并可直接查询，
> 对应的 DAO、Service 与 Servlet 将在后续阶段补充；在此之前请求返回 404。

### GET /api/knowledge —— 知识卡检索（登录）

| 参数 | 说明 |
|---|---|
| `dimension` | 按风味维度筛选（八维编码之一） |
| `goalType` | 按适用研发目标筛选 |
| `keyword` | 标题 / 候选配料 / 检索关键词模糊匹配 |
| `page` / `pageSize` | 默认 1 / 10 |

返回列表项含 `knowledgeCode`、`title`、`dimension`、`candidateIngredient`、
`amountMin` / `amountMax` / `amountUnit`、`referenceRange`（拼好的区间文本）。

### GET /api/knowledge/{code} —— 知识卡详情（登录）

按 `knowledgeCode` 返回单张卡的完整字段，额外带出 `mechanism`（起效原理）、
`riskNote`（风险提示）、`evidenceSource`（依据来源）与 `allergenTags`。

### GET /api/pairings —— 配料搭配关系（登录）

| 参数 | 说明 |
|---|---|
| `ingredient` | 按配料名筛选，主配料或搭配配料任一命中即返回 |
| `relationType` | `SYNERGY` 协同 / `MASKING` 掩蔽 / `ANTAGONISM` 拮抗 / `BALANCE` 平衡 |
| `dimension` | 按作用的风味维度筛选 |

### POST /api/ai/explain/{taskId} —— AI 结果解读（登录）

把已有分析结果交给模型，翻译成研发人员可直接阅读的解读文字。

```json
{ "code": 0, "data": { "scene": "RESULT_EXPLAIN", "text": "本次调整主要影响脂香…",
                       "fallbackUsed": false, "elapsedMs": 1820 } }
```

- 仅允许解读本人任务，越权返回 403；
- `ai.enabled=false`、未配置密钥或调用失败、超时时，返回引擎原有的 `explanation` 原文，
  且 `fallbackUsed = true`——**保证无网络环境下仍可完整演示**；
- 无论成功与否都会写入 `ai_call_log`。

### POST /api/ai/ask —— 知识库问答（登录）

```json
{ "question": "减糖 30% 之后甜味塌了，怎么补？", "goalType": "REDUCE_SUGAR" }
```

```json
{ "code": 0, "data": {
    "answer": "减糖后甜味下降但不宜继续加蔗糖，建议先做代糖复配…",
    "references": [ { "knowledgeCode": "UK-SWEET-003", "title": "代糖复配平衡后味" },
                    { "knowledgeCode": "UK-SWEET-002", "title": "甜菊糖苷高倍甜味补充" } ],
    "fallbackUsed": false } }
```

`references` 是本次回答实际引用的知识卡，前端应渲染为来源卡片，便于用户核对依据。
检索以维度、场景与关键词匹配为主，不依赖外部向量库，因此来源可完整追溯。

### POST /api/ai/draft —— 自然语言转调整草案（登录）

```json
{ "recipeId": 7, "instruction": "油脂降 25%，辣度降两成，保持鲜味" }
```

```json
{ "code": 0, "data": {
    "targetItems": [ { "ingredientName": "菜籽油", "amount": 6, "unit": "ml" } ],
    "note": "草案未入库，请确认后提交分析" } }
```

返回的是**草案，不写入数据库**。前端应在用户确认后再调用 `POST /api/analysis`，
由规则引擎重新计算——结论必须始终由可解释链路产生。

## 九、后台管理（均为「管理员」权限）

### 用户

| 接口 | 说明 |
|---|---|
| `GET /api/admin/users` | 参数 `keyword` / `role` / `status` / `page` / `pageSize`；返回值不含密码哈希 |
| `PUT /api/admin/users/{id}/role` | body `{ "role": "ADMIN" }`，取值 `USER` / `ADMIN` |
| `PUT /api/admin/users/{id}/status` | body `{ "status": 0 }`，1 启用 / 0 禁用 |

安全限制：管理员**不能禁用自己**，也**不能取消自己的管理员身份**（返回 400）。

### 文章

| 接口 | 说明 |
|---|---|
| `GET /api/admin/articles` | 支持 `categoryId` / `keyword` / `status`（0 草稿、1 发布、2 下架、3 删除） |
| `GET /api/admin/articles/categories` | 全部分类（含停用） |
| `POST /api/admin/articles` | 新增；`summary` 为空时按正文自动生成；`contentHash` = SHA-256(标题 + 清洗后正文) |
| `POST /api/admin/articles/sync` | 简化同步：请求体为空时返回**模拟检测结果**（不写库）；带 `items` 时逐条导入为草稿，重复项收集到 `duplicated` |
| `PUT /api/admin/articles/{id}` | 编辑（重复检测排除自身） |
| `DELETE /api/admin/articles/{id}` | 软删除（`status = 3`） |

去重策略：① 来源地址相同 → 409；② 清洗后正文指纹相同 → 409；③ 标题相似 → 不拦截，返回 `duplicateHint` 提示人工确认。

### 食材

| 接口 | 说明 |
|---|---|
| `GET /api/admin/ingredients` | 参数 `keyword` / `category` / `status` / `page` / `pageSize` |
| `GET /api/admin/ingredients/categories` | 全部分类名 |
| `POST /api/admin/ingredients` | 新增（八维必须 0-100，名称唯一） |
| `PUT /api/admin/ingredients/{id}` | 修改属性 |
| `DELETE /api/admin/ingredients/{id}` | 停用（`status = 0`，不物理删除，避免历史数据断链） |

### 分析任务

`GET /api/admin/tasks`：参数 `keyword` / `goalType` / `status` / `page` / `pageSize`，
返回 `{ page: PageResult, totalAll: 平台任务总数 }`；管理员仅可查看，不提供修改接口。

## 十、操作日志

管理端写操作（文章、食材、用户）成功后写入文件日志，位置按以下顺序解析：

1. JVM 参数 `-Dflavorlogic.log.file=...`
2. 环境变量 `FLAVORLOGIC_LOG_FILE`
3. `${catalina.base}/logs/flavorlogic-operations.log`
4. 系统临时目录

格式：`时间 | user=操作者 | ip=来源 | 动作 | 对象 | 结果`，工作台管理员视图展示最近 15 条。

## 十一、前端调用约定

- 所有请求走 `js/common.js` 的 `FL.get / FL.post / FL.put / FL.del`，内部统一处理 `{code,message,data}` 与
  401（跳登录页）、403（提示无权限）等状态；
- 页面渲染用户数据前统一 `FL.escape()`，仅文章正文使用后端白名单过滤后的 HTML；
- 列表页统一「加载中 / 空数据 / 请求失败」三态；危险操作先 `FL.confirm` 二次确认。
